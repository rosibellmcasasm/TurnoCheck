REFERENCIA VISUAL (opcional):
 • SI ADJUNTO una imagen de referencia: es un CONTRATO, no una sugerencia (protocolo
   REFERENCIA=CONTRATO al inicio de docs/sistema/16-DIRECCION-DE-ARTE.md). Extráela con su TABLA
   DE EXTRACCIÓN mirando la imagen, no de memoria (hex exactos, fuentes candidatas, radios,
   sombras, layout, tratamiento de gráficos y cards, densidad informativa). La referencia MANDA
   sobre la capa anti-IA y las tablas del 29, y cada pantalla clave pasa el TEST DE FIDELIDAD
   (screenshot al lado de la referencia; ≥2 desvíos = corregir tokens antes de declararla lista).
   Quiero ESE nivel de pulido o mejor, FIEL a la referencia.
 • SI NO ADJUNTO imagen: no me la pidas ni la des por existente. La dirección visual se DERIVA
   completa con el PASO 0 del 16 (brief → arquetipo → mundo del sujeto → paleta/tipografía/motion)
   + la TABLA DE LÍDERES del 16 (PASO 0.2bis: investiga Cal AI, MyFitnessPal, Strava, Fitbod y
   1-2 gigantes admirados; FUSIONA lo mejor de cada una) + las COMBINACIONES TIPOGRÁFICAS
   PROBADAS del 29 (fila fitness — prohibido inventar combinaciones que ninguna app grande use)
   + el banco del 54 SOLO para el dispositivo ownable. El modo (oscuro/claro) se deriva de mi
   audiencia — NO se asume dark por ser fitness, y aplica la capa anti-IA del 16.

PROCESO (sigue el ciclo profesional de docs/sistema/12-FLUJO-AGENTICO.md):
1. Dirección de arte: con referencia → extracción REFERENCIA=CONTRATO del 16; sin referencia →
   PASO 0 del 16 (TABLA DE LÍDERES primero, fusión de lo probado) + banco del 54 para el dispositivo. En ambos casos preséntame la FICHA-ARTE.md (paleta con hex,
   tipografía, craft, regla del acento, modo derivado y por qué) y ESPERA MI OK.
2. Define la idea, features (3-5 máx) y el App Brief siguiendo docs/sistema/01-IDEACION.md.
3. Diseña arquitectura y flujo con docs/sistema/04 y 15-PATRONES-UX.md.
4. DETENTE y muéstrame el plan visual + de pantallas antes de codear. ESPERA MI OK.
5. (tras mi OK) Construye aplicando RIGUROSAMENTE:
   - docs/sistema/14-LEYES-DE-DISENO.md (specs numéricas exactas)
   - docs/sistema/16-DIRECCION-DE-ARTE.md (identidad audaz y cohesiva, capa anti-IA)
   - docs/sistema/17-VISUALIZACION-DATOS.md (los gráficos del dashboard: anillos, barras, macros)
   - docs/sistema/15-PATRONES-UX.md (skeleton, empty states, micro-interacciones, háptica)
   - docs/sistema/11-DISENO-EMOCIONAL.md (personalidad, celebraciones, movimiento)
6. Verifica tsc + build + dev server en cada capa; cada pantalla se cierra con screenshot REAL
   a 375px puntuado por el SUBAGENTE revisor-visual (gate ≥36/40 y ≥16/20, + test de fidelidad
   si hubo referencia — regla 7 de CLAUDE.md). Test final: "si quito el logo, ¿se distingue de
   un template Y de las otras apps de este SO?" — y cierra actualizando ESTADO.md con el reporte
   de evidencia (ruta del screenshot + veredicto del revisor).

Personalidad sugerida: enérgica, motivadora, premium — el acento y el modo los DERIVA el PASO 0
del 16 según mi audiencia concreta (un acento audaz está bien; el combo neón+glow+dark por
